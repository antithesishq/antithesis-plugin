# Version 0.0.10 (2026-11-11)

- Given a free-form prompt instead of a module name, such as `/antithesis test the latest release of my system`, the skill plans a workflow: the chain of modules that gets from what already exists to what the user asked for. The new `references/workflows/MODULE.md` gives common shapes: set up a system, heal a workload after its system changed, and test a system and triage what breaks. Before starting, the agent reads every module in the plan, tells the user the plan, and asks all of its questions in one message ([#70](https://github.com/antithesishq/antithesis-plugin/pull/70), [#76](https://github.com/antithesishq/antithesis-plugin/pull/76))
- `workload`: the driver can be written in any language hegel can write a driver in: Rust, Go, Python, C++ and OCaml. The agent picks the language the user asks for, then the language of the system's client library, then Rust. New pages for each language (Rust, Go, C and C++, Python, OCaml, Java, .NET, JavaScript and TypeScript, plus a fallback) cover its Antithesis SDK, its instrumentation, its local coverage tool and its hegel driver, and replace the old `instrumentation.md` and `sdk.md`. The driver is now built with coverage instrumentation too, like the SUT. Base images come from one table, on Debian 13 (trixie). The agent looks up the latest release of the SDK, hegel and every build tool rather than copying a version from memory ([#72](https://github.com/antithesishq/antithesis-plugin/pull/72))
- `workload`: new workloads go under `antithesis/<workload>/`, with `config/`, `driver/` and `scripts/` directories, plus an `antithesis/README.md` that the agent keeps current. The agent writes a script for each command it repeats, such as launching or a local run, and keeps the config directory down to the config, since `snouty launch` copies all of it into the config image. `launch` checks the config directory before building ([#48](https://github.com/antithesishq/antithesis-plugin/pull/48))
- When the user gives no compute budget, a long unattended task uses 60 compute hours, across every module and run. The agent keeps working toward the user's goal until it's met, or until only the user can unblock it. While other work remains, it writes its questions to a file the user will see rather than ending its turn on one. The workload run loop raises runs from 12 toward 24 compute hours as the workload earns trust, and finishes when a 24-hour run passes its checks, which replaces the separate final run ([#46](https://github.com/antithesishq/antithesis-plugin/pull/46), [#76](https://github.com/antithesishq/antithesis-plugin/pull/76))
- `triage` and `debug`: the agent triages runs live instead of waiting for them to finish, and acts on results that are already final. Whenever a run is ready, even an unrelated one, it runs commands at the failing moment, and it does that before calling a cause found. While a new debug run gets ready, or a large log downloads, it works in the background, reading logs and starting a reproducer. With no run named, it asks the user which run to triage instead of guessing ([#66](https://github.com/antithesishq/antithesis-plugin/pull/66), [#69](https://github.com/antithesishq/antithesis-plugin/pull/69), [#47](https://github.com/antithesishq/antithesis-plugin/pull/47))
- `workload`: every image includes debugging tools, such as `curl`, `jq` and the SUT's admin CLI, and the local loop checks that they run. A debug session can't install tools, since the Antithesis environment has no internet access. With the stateful-clients pattern, client images include `socat` or another JSON-RPC tool, so a debug session can drive a client from a shell ([#47](https://github.com/antithesishq/antithesis-plugin/pull/47))
- `debug` and `triage`: the agent passes negative input hashes as they are, puts every option before the run ID, and never uses `--`. Log downloads go through `mktemp`, under file names that never start with the hash ([#45](https://github.com/antithesishq/antithesis-plugin/pull/45))
- The plugin's `mcp.json` defines snouty's MCP server (`snouty mcp`) for platforms that read the agent-plugins manifest. Claude Code doesn't start it ([#61](https://github.com/antithesishq/antithesis-plugin/pull/61), [#62](https://github.com/antithesishq/antithesis-plugin/pull/62), [#64](https://github.com/antithesishq/antithesis-plugin/pull/64), [#65](https://github.com/antithesishq/antithesis-plugin/pull/65))
- The Claude manifest adds documentation, support, privacy policy and terms of service links, and a new logo. Both manifests add the keyword "deterministic simulation testing" ([#60](https://github.com/antithesishq/antithesis-plugin/pull/60), [#38](https://github.com/antithesishq/antithesis-plugin/pull/38), [#64](https://github.com/antithesishq/antithesis-plugin/pull/64))
- New setup steps for Cursor, and shorter Replit steps that add the skill from GitHub ([#49](https://github.com/antithesishq/antithesis-plugin/pull/49))
- The agent passes `--detail` only to snouty commands whose `--help` lists it ([#56](https://github.com/antithesishq/antithesis-plugin/pull/56))

# Version 0.0.9 (2026-11-05)

- `workload`: the driver ends a timeline with an eventually instead of pausing faults in quiet periods. An eventually is a normal rule that, behind a rare draw, stops faults for good, waits for the system to recover, asserts what must hold once faults stop, and exits the driver to end the timeline. The driver page also explains hegel's swarm testing, which leaves a random subset of rules out of each timeline, and tells the agent to pace disruptive actions with a cooldown rather than a weight. The harness gives the driver no restart policy, and the local loop checks the eventually on its own ([#30](https://github.com/antithesishq/antithesis-plugin/pull/30))
- `launch`: always sets `SNOUTY_UNSTABLE_FEATURES=teams`, so `snouty launch --help` shows the flags the skill relies on, and always passes `--max-compute-hours`. When the user gives a compute budget, the agent adds up the hours of its finished and running runs before each launch, and stops rather than exceed it. Every run records the plugin version that launched it as `attrs.plugin_version` ([#28](https://github.com/antithesishq/antithesis-plugin/pull/28), [#33](https://github.com/antithesishq/antithesis-plugin/pull/33), [#35](https://github.com/antithesishq/antithesis-plugin/pull/35), [#36](https://github.com/antithesishq/antithesis-plugin/pull/36))
- Before a long unattended task, such as building a workload, the agent asks the user up front for everything it can foresee needing, such as a compute budget and permission to change their code, then works to the end. A property that fails without a clear cause keeps its assertion and is reported to the user as a possible bug ([#32](https://github.com/antithesishq/antithesis-plugin/pull/32))
- `workload`: the run loop classifies every failing property as a SUT bug, a workload bug or expected before changing anything, never relaunches an unchanged workload, and cancels a run still going before launching the next. The final report lists any step the agent skipped or changed ([#29](https://github.com/antithesishq/antithesis-plugin/pull/29))
- `debug`: the agent cancels each debug run it started as soon as it's done with it ([#29](https://github.com/antithesishq/antithesis-plugin/pull/29))
- A new reference page, `references/antithesis/faults.md`, describes what each fault does, how it ends, and how it interacts with a pause. The harness and log pages link to it ([#31](https://github.com/antithesishq/antithesis-plugin/pull/31))
- `triage`: the main agent reads each triage page only when it reaches the step that needs it, and leaves the log guide to the subagents that download logs ([#34](https://github.com/antithesishq/antithesis-plugin/pull/34))

# Version 0.0.8 (2026-11-04)

The first tagged release of the Antithesis plugin. It gives a coding agent one skill, `antithesis`, as the entry point to any task that involves Antithesis. The skill picks one of its modules from the request:

- `workload`: build or extend a workload for the system under test. A driver generates requests with [Hegel](https://www.hegel.dev) and starts the workload, the harness runs it under Docker Compose, and the agent iterates locally before it spends compute.
- `properties`: import the system's guarantees, or define new ones, and express them as Antithesis assertions.
- `launch`: launch a run of a workload with `snouty launch`, with fault flags.
- `triage`: monitor a run in progress, summarize a finished one, and root-cause its failures.
- `debug`: run commands inside Antithesis at a moment of a run, to debug a failure or a property.
- `patterns`: optional pieces that only some workloads need, such as client containers for stateful client libraries, and log forwarding.

The skill needs snouty 0.9.0 or later, Docker or Podman with Docker Compose, and jq. The plugin installs on Claude Code, Codex and Cursor from this repository's marketplace, and has setup notes for Devin and Replit.

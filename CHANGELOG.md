# Version 0.1.0-rc.1 (2026-11-11)

- `workload`: the driver can be written in any language that hegel supports with a main entry point: Rust, Go, C++, Python and OCaml. The agent uses the language the user asks for. If the user names none, it uses the language of the system's client library, and Rust after that. Each language now has its own page covering its Antithesis SDK, coverage instrumentation, local coverage tool and hegel driver. These pages replace the old instrumentation and SDK pages. Java, .NET, JavaScript/TypeScript and other languages also get pages for instrumenting the system under test. The driver is now built with coverage instrumentation too. A new images page sets the base images, all on Debian 13 (trixie). The skill names assertion types in one way for every language, such as `assert_always` ([#72](https://github.com/antithesishq/antithesis-plugin/pull/72))
- A new `workflows` module handles free-form prompts, such as `/antithesis test the latest release of my system`. The agent finds the user's goal and what already exists, then plans a chain of modules to reach the goal. It reads every module in the plan up front and tells the user the plan. In the same message, it asks every question the plan will raise. Examples cover setting up a system, healing a workload after its system changed, and testing a system and triaging what breaks. A first argument that names a module still goes straight to that module ([#70](https://github.com/antithesishq/antithesis-plugin/pull/70), [#76](https://github.com/antithesishq/antithesis-plugin/pull/76))
- On a long unattended task, the agent keeps working toward the user's goal until it is met, or until it is blocked on something only the user can decide. It no longer stops at the last step of a module. While other work remains, it writes questions to a file the user will see instead of ending its turn on them. If the user gives no compute budget, the whole task gets 60 compute hours, across every module and run. `launch` checks every launch against that budget. The `workload` run loop starts at 12 compute hours and raises that toward 24. It finishes once a 24-hour run passes its checks, which replaces the separate final run ([#46](https://github.com/antithesishq/antithesis-plugin/pull/46), [#76](https://github.com/antithesishq/antithesis-plugin/pull/76))
- `triage` and `debug`: when investigating a failure, the agent always runs commands at the failing moment. It prefers any ready run, which costs nothing, over starting a debug run. When a counterexample appears in a run that is still in progress, it runs commands there. It never sits idle waiting for a debug run to get ready: meanwhile it reads the logs and starts on a reproducer. Root-cause analysis always runs commands at and around the failing moment. Reports cite command output as well as log lines ([#47](https://github.com/antithesishq/antithesis-plugin/pull/47), [#69](https://github.com/antithesishq/antithesis-plugin/pull/69))
- `triage`: the agent triages runs live and never waits for a run to finish first. The `workload` run loop checks results as they arrive, and it can fix a workload bug before the run ends. When the user doesn't say which run to triage, the agent asks instead of guessing ([#66](https://github.com/antithesishq/antithesis-plugin/pull/66))
- `workload` and `launch`: a new default layout puts each workload under `antithesis/<workload>/`, with `config/`, `driver/` and `scripts/` directories. It adds a short `antithesis/README.md`, and scripts for the commands the agent repeats, such as launching. Before each launch, `launch` checks that the config directory holds only the compose file or manifests, the files they mount and env files. This keeps large config images out of every launch. The local loop saves each run's output to a fresh directory outside the config directory ([#48](https://github.com/antithesishq/antithesis-plugin/pull/48))
- `workload`: workload images now include debugging tools, such as `curl`, `jq` and the system's admin CLI, because tools can't be installed inside Antithesis. The local loop checks that each tool runs. The stateful-clients pattern adds a JSON-RPC tool to each client image, so a debug session can drive the client from a shell ([#47](https://github.com/antithesishq/antithesis-plugin/pull/47))
- `debug` and `triage`: the agent puts every option before the run ID, passes a negative input hash as it is, and never uses `--`. Logs download to a `mktemp` file and are then renamed to `log_<hash>.ndjson`, so no file name starts with a `-` ([#45](https://github.com/antithesishq/antithesis-plugin/pull/45))
- The agent passes `--detail` only to snouty commands whose `--help` lists it ([#56](https://github.com/antithesishq/antithesis-plugin/pull/56))
- Install: a new page gives setup steps for Cursor, and Replit now installs the skill directly from GitHub. The plugin ships an agent-plugins `mcp.json` that declares the `snouty` MCP server for platforms other than Claude Code. The Claude Code manifest adds documentation, support, privacy policy and terms of service URLs, and uses an SVG logo. Both manifests add a "deterministic simulation testing" keyword ([#38](https://github.com/antithesishq/antithesis-plugin/pull/38), [#49](https://github.com/antithesishq/antithesis-plugin/pull/49), [#60](https://github.com/antithesishq/antithesis-plugin/pull/60), [#61](https://github.com/antithesishq/antithesis-plugin/pull/61), [#62](https://github.com/antithesishq/antithesis-plugin/pull/62), [#64](https://github.com/antithesishq/antithesis-plugin/pull/64), [#65](https://github.com/antithesishq/antithesis-plugin/pull/65))

# Version 0.0.9 (2026-11-05)

- `workload`: the driver ends a timeline with an eventually instead of pausing faults in quiet periods. An eventually is a normal rule that, behind a rare draw, stops faults for good, waits for the system to recover, asserts what must hold once faults stop, and exits the driver to end the timeline. The driver page also explains hegel's swarm testing, which leaves a random subset of rules out of each timeline, and tells the agent to pace disruptive actions with a cooldown rather than a weight. The harness gives the driver no restart policy, and the local loop checks the eventually on its own ([#30](https://github.com/antithesishq/antithesis-plugin/pull/30))
- `launch`: always sets `SNOUTY_UNSTABLE_FEATURES=teams`, so `snouty launch --help` shows the flags the skill relies on, and always passes `--max-compute-hours`. When the user gives a compute budget, the agent adds up the hours of its finished and running runs before each launch, and stops rather than exceed it. Every run records the plugin version that launched it as `attrs.plugin_version` ([#28](https://github.com/antithesishq/antithesis-plugin/pull/28), [#33](https://github.com/antithesishq/antithesis-plugin/pull/33), [#35](https://github.com/antithesishq/antithesis-plugin/pull/35), [#36](https://github.com/antithesishq/antithesis-plugin/pull/36))
- Before a long unattended task, such as building a workload, the agent asks the user up front for everything it can foresee needing, such as a compute budget and permission to change their code, then works to the end. A property that fails without a clear cause keeps its assertion and is reported to the user as a possible bug ([#32](https://github.com/antithesishq/antithesis-plugin/pull/32))
- `workload`: the run loop classifies every failing property as a SUT bug, a workload bug or expected before changing anything, never relaunches an unchanged workload, and cancels a run still going before launching the next. The final report lists any step the agent skipped or changed ([#29](https://github.com/antithesishq/antithesis-plugin/pull/29))
- `debug`: the agent cancels each debug run it started as soon as it's done with it ([#29](https://github.com/antithesishq/antithesis-plugin/pull/29))
- A new reference page, `references/antithesis/faults.md`, describes what each fault does, how it ends, and how it interacts with a pause. The harness and log pages link to it ([#31](https://github.com/antithesishq/antithesis-plugin/pull/31))
- `triage`: the main agent reads each triage page only when it reaches the step that needs it, and leaves the log guide to the subagents that download logs ([#34](https://github.com/antithesishq/antithesis-plugin/pull/34))

# Version 0.0.8 (2026-11-04)

The first tagged release of the Antithesis plugin. It gives a coding agent one skill, `antithesis`, as the entry point to any task that involves Antithesis. The skill picks one of its modules from the request:

- `workload`: build or extend a workload for the system under test. A driver generates requests with [Hegel](https://www.hegel.dev) and starts the workload, the harness runs it under Docker Compose, and the agent iterates locally before it spends compute.
- `properties`: import the system's guarantees, or define new ones, and express them as Antithesis assertions.
- `launch`: launch a run of a workload with `snouty launch`, with fault flags.
- `triage`: monitor a run in progress, summarize a finished one, and root-cause its failures.
- `debug`: run commands inside Antithesis at a moment of a run, to debug a failure or a property.
- `patterns`: optional pieces that only some workloads need, such as client containers for stateful client libraries, and log forwarding.

The skill needs snouty 0.9.0 or later, Docker or Podman with Docker Compose, and jq. The plugin installs on Claude Code, Codex and Cursor from this repository's marketplace, and has setup notes for Devin and Replit.

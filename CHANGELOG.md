# Version 0.1.1 (2026-11-13)

- When users give no compute budget for a long unattended task, the agent now defaults to 300 compute hours instead of 60. It's also told to spend the budget on any run that moves the goal forward, not to hold runs back just to save hours ([#99](https://github.com/antithesishq/antithesis-plugin/pull/99)).
- Properties and patterns: the agent now uses log forwarding only for conditions that no one node can see, such as at most one leader per term. When a node can see a condition from its own state or the messages it handles, the agent puts the assertion in that node's code. For example, a follower can check that it never truncates a committed entry. The agent also no longer adds `assert_sometimes` on internal states that every startup reaches, such as a node adopting a higher term in the first election ([#100](https://github.com/antithesishq/antithesis-plugin/pull/100)).
- Getting help: the README has a new "Getting help" section. When the agent is stuck on something outside the user's control, it now points the user to the right place: support@antithesis.com for their tenant or runs, GitHub issues for bugs in the plugin or Snouty, and the Antithesis Discord for questions ([#98](https://github.com/antithesishq/antithesis-plugin/pull/98)).

# Version 0.1.0 (2026-11-11)

- **Breaking**: **snouty 0.10.0 or later**: the skill and the snouty MCP server now need snouty 0.10.0. The agent no longer sets `SNOUTY_UNSTABLE_FEATURES=teams` for `snouty launch`, and the plugin's `mcp.json` no longer sets `SNOUTY_UNSTABLE_FEATURES=mcp`, because snouty 0.10.0 makes those features stable. With an older snouty, launches fail on `--max-compute-hours` and the MCP server doesn't start. Run `snouty update`, or reinstall snouty if you didn't install it with the installer script. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78), [#83](https://github.com/antithesishq/antithesis-plugin/pull/83))
- **Debugging sessions**: the skill now uses the name "debugging session", as the docs and `snouty debug` do. During triage the agent always runs commands at the failing moment. It uses an existing ready run if there is one, and otherwise starts a debugging session. It always passes a `--duration` to the session and cancels it when done. Debugging sessions no longer count against the task's compute budget. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78))
- **Properties checks**: the local check confirms three things about each assertion: it's implemented correctly, it matches a real guarantee, and it should be reachable in Antithesis. Many assertions, such as those that need faults, can't be reached locally. Once the local loop stops giving answers, the agent moves on to a short run. In the short run, it first confirms that the exploration assertions leading up to each guarantee pass, then the guarantee's own assertions. If the run never reaches the guarantee, the agent launches a longer run or changes the workload. When importing guarantees, the agent offers the next batch in its report instead of stopping to ask. `assertions.md` now forbids only a reachable or sometimes assertion added just to show that the same check ran. Log forwarding asks for one assertion per kind of parsed line. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78))
- **Language builds**: Rust passes its instrumentation flags as `cargo build --config` options in the Antithesis Dockerfile, not in `.cargo/config.toml`. Go builds with cgo enabled, because without cgo Antithesis gets no coverage. Go's local coverage build keeps the assertion catalog (`ANTITHESIS_SKIP_COVERAGE=true` with `-toolexec`). C++ builds with `clang-22`, because clang 17–20 can't link assertions that share a message or location across files. Python is now treated as a language Antithesis doesn't instrument. Its code is still cataloged through `/opt/antithesis/catalog/`. The harness instruments the driver, and copies `/symbols`, only when the driver's language allows it. The log forwarder isn't instrumented. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78))
- **Faults**: `faults.md` now matches the docs. Node throttling is part of `resilient`. CPU modulation and clock skips act on the whole machine. Thread pausing acts on one thread at a time, and no machine, node or process can be excluded from it. A clock skip is either a jitter, which jumps back later, or an offset, which doesn't. Pausing faults doesn't stop a jitter that's already in progress. `logs.md` explains that a kill or stop has `max_duration` `"0"` only for a Kubernetes pod, which Kubernetes restarts. The driver's eventually skips `$ANTITHESIS_STOP_FAULTS` when it's unset, as it is in the local loop. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78))
- **snouty commands**: every example puts the run ID right after the subcommand, followed by the options, such as `snouty runs exec "$RUN_ID" --container client1 ...`. It still never uses `--` before a negative input hash. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78))
- **Smaller fixes**: a launcher is now described as the kind of run to start, and run discovery filters by launcher and test name rather than by webhook and source. A workload launches with `basic_test` unless the user names another launcher. The run loop ends when a 24-compute-hour run passes its checks. The stateful-clients example builds from the parent directory (`context: ..`). The instrumentation docs link points to the current page. ([#78](https://github.com/antithesishq/antithesis-plugin/pull/78))

# Version 0.0.10 (2026-11-11)

- **Workflows from free-form prompts**: a new `workflows` module. When `/antithesis` gets a free-form prompt instead of a module name, the agent works out the user's goal and plans the chain of modules that reaches it. Common plans are setting up a system, healing a workload after its system changed, and testing a system and triaging what breaks. Before starting, the agent reads every planned module and sends one message with the plan and all the questions it will need answered. At the end it reports the workflow it ran. A first argument that names a module still goes straight to that module. ([#70](https://github.com/antithesishq/antithesis-plugin/pull/70), [#76](https://github.com/antithesishq/antithesis-plugin/pull/76))
- **Long unattended tasks**: the agent keeps working toward the user's goal until the goal is met or it's blocked on something only the user can decide. It no longer stops at the last step of a module. While other work remains, it writes questions to a file the user will see and keeps going, instead of ending its turn on a question. If the user gives no compute budget, the default is 60 compute hours for the whole task, across every module and run, and the launch module's budget check counts against it. ([#46](https://github.com/antithesishq/antithesis-plugin/pull/46), [#76](https://github.com/antithesishq/antithesis-plugin/pull/76))
- **Workload module for any language**: the driver is no longer Rust only. The agent picks the driver's language in this order: the language the user asks for, then the language of the system's client library, then Rust. Hegel drivers are supported in Rust, Go, Python, C++ and OCaml. The new language pages for Rust, Go, C and C++, Python, OCaml, Java, .NET and JavaScript/TypeScript, plus a fallback page, cover each language's Antithesis SDK, instrumentation, local coverage and hegel driver. The driver is now instrumented like the system under test. A new image table pins the build and runtime images to the current Debian stable release (trixie). Assertions are named the same way in every language, such as `assert_always`. ([#72](https://github.com/antithesishq/antithesis-plugin/pull/72))
- **Default workload layout**: unless the user or the repository says otherwise, a new workload goes under `antithesis/<workload>/`, split into `config/`, `driver/` and `scripts/` directories, with a short `antithesis/README.md`. The agent writes scripts for the commands it repeats, such as launching and the local loop. Before launching, it checks that the config directory holds only the config, because `snouty launch` copies all of it into the config image. ([#48](https://github.com/antithesishq/antithesis-plugin/pull/48))
- **Runs commands at failing moments**: when any ready run is available, the agent runs commands at failing moments while triaging and debugging, rather than relying only on logs. While a run is still in progress, it runs commands there. A new debug run starts in the background, and the agent reads logs while it waits. ([#69](https://github.com/antithesishq/antithesis-plugin/pull/69), [#47](https://github.com/antithesishq/antithesis-plugin/pull/47))
- **Debug tools in workload images**: workload images include debug tools, such as `curl`, `jq` and the system's admin CLI, and the local loop checks that they run. Stateful client containers get a JSON-RPC tool such as `socat`. The tools have to be in the images because nothing can be installed in the Antithesis environment. ([#47](https://github.com/antithesishq/antithesis-plugin/pull/47))
- **Live triage**: the agent never waits for a run to finish before triaging it. During the workload's run loop, it follows each run live in monitor mode and acts on final results as they arrive. When the user names no run, the agent asks which one to use instead of guessing. The workload's run loop starts at 12 compute hours, moves toward 24, and ends when a 24-hour run passes its checks. ([#66](https://github.com/antithesishq/antithesis-plugin/pull/66), [#46](https://github.com/antithesishq/antithesis-plugin/pull/46))
- **Negative input hashes**: the agent puts every option before the run ID, never passes `--` before a negative input hash, and never starts a log file name with the hash. Logs download through `mktemp` files. ([#45](https://github.com/antithesishq/antithesis-plugin/pull/45))
- **`--detail`**: the agent passes `--detail` only to snouty commands whose `--help` lists it. ([#56](https://github.com/antithesishq/antithesis-plugin/pull/56))
- **snouty MCP server**: the plugin ships an agent-plugins `mcp.json` that starts snouty's MCP server (`snouty mcp`) on platforms that read that file. Claude Code doesn't load it. ([#61](https://github.com/antithesishq/antithesis-plugin/pull/61), [#62](https://github.com/antithesishq/antithesis-plugin/pull/62), [#64](https://github.com/antithesishq/antithesis-plugin/pull/64), [#65](https://github.com/antithesishq/antithesis-plugin/pull/65))
- **Cursor and Replit setup**: new Cursor setup docs. Replit now installs the skill directly from the GitHub repository. ([#49](https://github.com/antithesishq/antithesis-plugin/pull/49))
- **Plugin listing**: a new SVG logo. The Claude manifest gains documentation, support, privacy policy and terms of service URLs, and the manifests gain a "deterministic simulation testing" keyword. ([#38](https://github.com/antithesishq/antithesis-plugin/pull/38), [#60](https://github.com/antithesishq/antithesis-plugin/pull/60), [#64](https://github.com/antithesishq/antithesis-plugin/pull/64))

# Version 0.0.9 (2026-11-05)

- `workload`: the driver ends a timeline with an eventually instead of pausing faults in quiet periods. An eventually is a normal rule that, behind a rare draw, stops faults for good, waits for the system to recover, asserts what must hold once faults stop, and exits the driver to end the timeline. The driver page also explains hegel's swarm testing, which leaves a random subset of rules out of each timeline, and tells the agent to pace disruptive actions with a cooldown rather than a weight. The harness gives the driver no restart policy, and the local loop checks the eventually on its own ([#30](https://github.com/antithesishq/antithesis-plugin/pull/30))
- `launch`: always sets `SNOUTY_UNSTABLE_FEATURES=teams`, so `snouty launch --help` shows the flags the skill relies on, and always passes `--max-compute-hours`. When the user gives a compute budget, the agent adds up the hours of its finished and running runs before each launch, and stops rather than exceed it. Every run records the plugin version that launched it as `attrs.plugin_version` ([#28](https://github.com/antithesishq/antithesis-plugin/pull/28), [#33](https://github.com/antithesishq/antithesis-plugin/pull/33), [#35](https://github.com/antithesishq/antithesis-plugin/pull/35), [#36](https://github.com/antithesishq/antithesis-plugin/pull/36))
- Before a long unattended task, such as building a workload, the agent asks the user up front for everything it can foresee needing, such as a compute budget and permission to change their code, then works to the end. A property that fails without a clear cause keeps its assertion and is reported to the user as a possible bug ([#32](https://github.com/antithesishq/antithesis-plugin/pull/32))
- `workload`: the run loop classifies every failing property as a SUT bug, a workload bug or expected before changing anything, never relaunches an unchanged workload, and cancels a run still going before launching the next. The final report lists any step the agent skipped or changed ([#29](https://github.com/antithesishq/antithesis-plugin/pull/29))
- `debug`: the agent cancels each debug run it started as soon as it's done with it ([#29](https://github.com/antithesishq/antithesis-plugin/pull/29))
- A new reference page, `references/antithesis/faults.md`, describes what each fault does, how it ends, and how it interacts with a pause. The harness and log pages link to it ([#31](https://github.com/antithesishq/antithesis-plugin/pull/31))
- `triage`: the main agent reads each triage page only when it reaches the step that needs it, and leaves the log guide to the subagents that download logs ([#34](https://github.com/antithesishq/antithesis-plugin/pull/34))

# Version 0.0.8 (2026-11-04)

The first tagged release of the Antithesis plugin. It gives a coding agent one skill, `antithesis`, as the entry point to any task that involves Antithesis. The skill picks one of its modules from the request:

- `workload`: build or extend a workload for the system under test. A driver generates requests with [Hegel](https://www.hegel.dev) and starts the workload, the harness runs it under Docker Compose, and the agent iterates locally before it spends compute.
- `properties`: import the system's guarantees, or define new ones, and express them as Antithesis assertions.
- `launch`: launch a run of a workload with `snouty launch`, with fault flags.
- `triage`: monitor a run in progress, summarize a finished one, and root-cause its failures.
- `debug`: run commands inside Antithesis at a moment of a run, to debug a failure or a property.
- `patterns`: optional pieces that only some workloads need, such as client containers for stateful client libraries, and log forwarding.

The skill needs snouty 0.9.0 or later, Docker or Podman with Docker Compose, and jq. The plugin installs on Claude Code, Codex and Cursor from this repository's marketplace, and has setup notes for Devin and Replit.
